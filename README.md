# Konnect POI Intelligence & Ranking System

A prototype ML pipeline that transforms a POI catalog + traveler/trip
context + historical interactions into a **personalized, ranked, and
weighted** list of POIs for a downstream itinerary planner.

See `docs/TECHNICAL_DOC.md` for the full design rationale and
`docs/example_results.md` for sample output across five traveler
scenarios (generated by `scripts/run_demo.py`).

**The demo is deterministic and machine-independent** — every random draw
is seeded, and `scripts/run_demo.py` pins BLAS/OpenMP thread counts before
numpy loads, because threaded floating-point reductions otherwise wobble in
the last bits and can flip a tree split. Verified byte-identical across
repeated runs, across 1/4/8/16 threads, and across `PYTHONHASHSEED` values.
The numbers below are exactly what you will see.

## Pipeline

Stage names follow the assignment's Deliverable A pipeline:

```
Raw POI Data + Traveler/Trip Context + Historical Interactions
    |
    v  Data Preparation          src/data_prep.py
    v  POI Representation        src/features.py, src/text_features.py
    v  Traveler Representation   src/traveler_profile.py
    v  Candidate Generation      src/candidate_gen.py
    v  Personalized Ranking      src/ranker.py
    v  POI Scoring               src/context_scoring.py  (+ src/explain.py)
    v  Evaluation                src/evaluate.py
    |
    v
Ranked & weighted POI list -> downstream itinerary planner
```

`src/pipeline.py` orchestrates the serving path end to end.

## Setup

Requires Python 3.10+. Dependencies are pinned in `requirements.txt` to the
exact versions the reported numbers were produced with.

### Standard setup (`venv` + `pip`, no extra tools needed)

> If a `venv/` directory is already present from a previous checkout, delete it
> and recreate it. Do not reuse it.

```bash
git clone https://github.com/Govii06/Konnect-poi-ranker.git
cd konnect-poi-ranker

python -m venv venv
```

Activate it:
```bash
# macOS / Linux
source venv/bin/activate

# Windows (PowerShell)
venv\Scripts\Activate.ps1
```
> If PowerShell blocks this with an execution-policy error, run
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` first, then retry.

Install dependencies:
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### Optional: [uv](https://docs.astral.sh/uv/) instead of `venv`/`pip`

If you already have `uv` installed, it's faster and manages its own Python
interpreter, sidestepping system-Python quirks entirely:
```bash
uv venv --python 3.12
uv pip install -r requirements.txt
uv run python data/generate_data.py
uv run python -m scripts.run_demo
```
(Everywhere below, prefix commands with `uv run` if you used this path.)

### Troubleshooting

- **`pip install` tries to compile pandas/numpy from source, or fails with an
  SSL certificate error**: your `python` likely resolves to a non-standard
  build (e.g. an MSYS2/mingw install on Windows) that lacks prebuilt-wheel
  support for the pinned versions. Check with `where python` (Windows) or
  `which python` (macOS/Linux) — it should point to a standard python.org or
  Microsoft Store install, not an MSYS2/Cygwin path. Reinstalling from
  [python.org](https://www.python.org/downloads/) resolves this, or use the
  `uv` path above, which sidesteps the system interpreter entirely.
- **`Access is denied` creating the venv on Windows**: the target folder is
  likely inside a synced/locked directory (e.g. OneDrive) or needs Admin
  rights. Try a plain local path (e.g. `C:\projects\...`) and/or run
  PowerShell as Administrator.

## 1. Generate the synthetic dataset

The CSVs are committed, so this step is optional — run it only to
regenerate them from scratch (it is seeded, and reproduces the same
files):

```bash
python data/generate_data.py
```

This writes `data/pois.csv` (320 POIs + 8 injected near-duplicates),
`data/travelers.csv` (60 synthetic travelers, trips of 2–10 nights), and
`data/interactions.csv` (976 historical interactions) for a single
destination ("Lisbon"). Interactions are sampled from an internal
ground-truth affinity function, so there is real learnable signal in
the data (not pure noise).

## 2. Run the full demo (train + evaluate + 5 scenarios)

```bash
python -m scripts.run_demo
```

This will:
1. Load and clean the POI catalog.
2. Build traveler profiles (explicit + implicit) for all 60 travelers.
3. Fit the TF-IDF text model over POI descriptions.
4. Train the ranking model on interaction-derived labels, using
   leave-one-out behavioral features (avoids target leakage) and
   implicit negative sampling.
5. Report Precision@10 / Recall@10 / NDCG@10 on held-out interactions
   **against random and popularity-only baselines**, plus the candidate
   recall ceiling, personalization, long-tail coverage, constraint
   compatibility, and category diversity.
6. Run 5 traveler scenarios — local-experience, history, family, a true
   cold-start traveler with zero data, and a returning traveler with
   real interaction history — printing and saving their top-ranked POIs
   with scores, confidence, top contributing signals, and explanations
   to `docs/example_results.md`.

### What you should see

```
=== Ranking metrics vs. baselines (held-out interactions, K=10) ===
                     P@10     R@10   NDCG@10
  random           0.0080   0.0291    0.0340
  popularity       0.0037   0.0108    0.0151
  MODEL            0.0130   0.0451    0.0635
  -> lift over random: 1.63x | lift over popularity: 3.50x

  CANDIDATE RECALL CEILING    : 0.316   <- hard upper bound on Recall@K

  personalization (1 - Jaccard) : 0.922
  long-tail coverage            : 0.545
  constraint compatibility      : 0.995
  category diversity            : 0.706
```

The model beats both baselines on all three ranking metrics. Absolute
Precision@10 is structurally small — each traveler has only ~2.6
held-out relevant POIs, so a perfect ranker caps near 0.26; the
meaningful figure is the lift. The candidate recall ceiling of 0.32
shows that retrieval, not ranking, is the binding constraint. See
`docs/TECHNICAL_DOC.md` §9.

## Using the pipeline programmatically

```python
import pandas as pd
from src.pipeline import POIIntelligencePipeline

pois = pd.read_csv("data/pois.csv")
travelers = pd.read_csv("data/travelers.csv")
interactions = pd.read_csv("data/interactions.csv")

pipeline = POIIntelligencePipeline()
pipeline.fit(pois, travelers, interactions)

recommendations = pipeline.recommend("U000", top_k=10)
# -> [{"poi_id": ..., "name": ..., "category": ...,
#      "score": ...,                  # final utility, preference x context gate
#      "preference_weight": ...,      # ML ranker output
#      "context_compatibility": ...,  # budget/mobility/availability
#      "confidence": ...,
#      "reasons": [...],              # human-readable explanations
#      "top_signals": [{"feature": ..., "value": ..., "contribution": ...}]},
#     ...]
```

`top_signals` names the features that actually drove each POI's score
(`feature_value x global_importance`, ranked by magnitude) so a
downstream consumer can display *why* a POI was surfaced.

## Repository layout

```
data/
  generate_data.py     synthetic dataset generator
  pois.csv, travelers.csv, interactions.csv   (generated)
src/
  data_prep.py          POI cleaning
  traveler_profile.py   explicit + implicit traveler representation,
                        leave-one-out views for leak-free training
  text_features.py      TF-IDF over POI descriptions -> text_similarity
  candidate_gen.py      multi-channel candidate retrieval
  features.py           shared (traveler, POI) feature engineering
  ranker.py             training-set construction + GBM ranking model
  context_scoring.py    budget/mobility/availability gate + final utility
  explain.py            template-based explanations
  pipeline.py           end-to-end orchestrator
  evaluate.py           Precision/Recall/NDCG, baselines, candidate recall
                        ceiling, personalization, long-tail, diversity
scripts/
  run_demo.py           trains, evaluates, runs 5 scenarios
docs/
  TECHNICAL_DOC.md       design document (read this first)
  example_results.md    generated scenario output (after running demo)
```
